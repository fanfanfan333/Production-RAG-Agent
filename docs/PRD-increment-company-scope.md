# 增量 PRD：公司注册表 · 测试公司作用域收敛 · 文档三层标注

> 类型：已有系统增量需求（简单增量 PRD，不含竞品/市场分析）
> 语言：中文
> 范围：只描述需求与产品设计，不含代码与数据库表结构

---

## 1. 变更目标

当前系统有 5 个租户、三层知识库（个人 / 部门 / 公司），但存在三个用户痛点：

1. **公司混在一起分不清**：文档页把两家公司的部门文档混在同一个列表里，标签只写"部门"，用户无法分辨某份文档属于哪家公司；
2. **admin 无法按测试公司隔离**：平台管理员 `admin` 当前是跨公司可见，无法"只在自己创建的测试公司内"工作，测试公司之间、与其他公司之间也没有硬隔离；
3. **公司无法创建 / 改名**：公司是从用户数据 `GROUP BY` 推导出来的，只能"先有用户再有公司"，无法先创建公司再注册，也无法改名（改名本应只是展示名变化，不应迁移成员 / 文档 / 向量）。

本轮要把"公司"从**推导概念**升级为**可管理的一等注册实体**，并以此为基础完成文档标注、身份验证绑定、admin 作用域收敛与文档页筛选。

---

## 2. 用户故事

### 平台管理员 admin
- 作为 admin，我要**先在注册表里创建公司**，以便新用户提交身份验证时能选到一个"已注册"的公司，而不是自由输入。
- 作为 admin，我要**给公司改名**（如把"转入检索公司bjld8"改为"测试公司1"），以便对外显示一个清晰的名字，且不改动成员、文档与向量数据。
- 作为 admin，我要**在文档页按公司筛选**（全部公司 / 指定公司），以便专注查看某一家测试公司的文档。
- 作为 admin，我要**只能看到自己创建的测试公司的全部文档（含该公司的个人库文档）**，并且**检索也只能命中这些公司的文档**，以便在测试场景下不越界看到其他公司的内部内容。

### 测试公司成员
- 作为新注册用户，我要**提交身份验证并在 admin 同意后进入指定公司**，以便获得该公司的测试账号与对应知识库访问权。
- 作为测试公司成员，我要**在文档列表里看到带公司名与部门名的标签**（如"测试公司1 · 营销部门"），以便一眼分辨文档归属。

### 普通公司成员
- 作为普通公司成员，我要**我的个人知识库对他人（包括 admin）保持私密**，以便个人资料不被越权查看。
- 作为普通公司成员，我要**只能看到本公司范围内的文档**，以便不同公司之间严格隔离。

## 3. 需求池（P0 / P1 / P2）

### P0（必须）

**P0-1 文档三层标注（R1）**
- 部门文档标签 = 图标(Users) + 层级词"部门" + 公司名 + 部门名，渲染为 `测试公司1 · 营销部门`（公司名 · 部门名）。
- 公司文档标签 = 图标(Building2) + 层级词"公司" + 公司名，渲染为 `测试公司1`。
- 个人文档标签 = 图标(Lock) + 层级词"个人"，渲染为 `个人`（不显示公司名）。
- 三种层级图标（Lock / Users / Building2）必须保留；"个人 / 部门 / 公司"三个层级词必须仍可辨识（建议保留层级词，公司名/部门名作为附加信息）。
- 验收：给定一条 department 文档，列表标签文本包含公司名与部门名且图标为 Users；给定 tenant 文档，标签文本为公司名且图标为 Building2；给定 private 文档，标签文本为"个人"且图标为 Lock。
- 边界：公司名或部门名缺失时，退化为仅显示层级词（不显示 `·`），不得显示 `undefined`/空白分隔符。

**P0-2 公司注册表：创建公司（R2）**
- admin 可在管理后台创建公司（输入公司名 → 生成/登记该公司）。
- 创建后新公司在公司注册表中可见，可作为身份验证的可选目标。
- 公司名唯一（见 P0-3）。
- 验收：admin 创建公司 X 后，`GET /staff/companies`（或注册表查询）能返回 X；成员提交身份验证时，X 出现在公司下拉候选中。

**P0-3 公司重名处理（R2 边界）**
- 公司名唯一：创建同名公司（忽略首尾空格、大小写）时拒绝，返回明确错误提示"公司已存在"。
- 验收：已存在"测试公司1"时，再次创建"测试公司1"（或" 测试公司1 "）被拒绝并给出可读提示。

**P0-4 公司改名（R2）**
- admin 可将公司展示名从旧名改为新名；**tenant_id 不变**，成员归属、文档归属、向量数据零迁移。
- 本轮需完成：`转入检索公司bjld8` → `测试公司1`；`转入检索公司1z5pp` → `测试公司2`。
- 改名后，文档标签中的公司名同步显示为新名。
- 验收：改名后，(a) 该公司成员数量、文档数量与改名前后一致；(b) 文档标签显示新公司名；(c) 该公司 tenant_id 未变化（通过既有租户标识核对）。

**P0-5 身份验证绑定已注册公司（R3）**
- 身份验证表单的"公司"字段从**自由输入**改为**绑定已注册公司**（下拉/选择，来源为公司注册表）。
- 公司必须是已注册公司；提交不存在的公司时**拒绝提交并明确提示**"请先由管理员注册该公司"。
- 新用户提交身份验证后，**必须经 admin 同意**才成为该公司的测试账号并进入该公司；未同意前不获得该公司访问权。
- 验收：提交指向已注册公司 X 的申请 → admin 同意 → 该用户归属 X 且可见 X 范围文档；提交指向未注册公司的申请 → 被拒绝并提示；申请处于 pending 时该用户不可见 X 的文档。

**P0-6 admin 作用域收敛 —— 列表可见范围（R4，本轮最重要）**
- admin 不再跨全平台可见；admin **只能看到"自己创建的测试公司"的全部文档**。
- 在该可见范围内，**包含这些测试公司的个人(private)文档**（这是仅限 admin 自建测试公司的窄口径例外）。
- admin **不能看到其他公司（非自己创建的测试公司）的内部文档**。
- 测试公司之间、测试公司与其它公司之间**硬隔离**。
- 边界（默认值）：admin 尚未创建任何测试公司时，文档列表返回**空列表**并给出引导（"暂无测试公司，请先创建公司"），不得回退为"全平台可见"。
- 验收：以 admin 身份查询文档列表，结果集仅包含其自建测试公司的文档（含该公司 private 文档），不包含其它公司任何文档；若 admin 未创建测试公司，则列表为空。

**P0-7 admin 作用域收敛 —— 检索可见范围（R4）**
- admin 的**检索也只能命中其自建测试公司的文档**（含该公司 private 文档），与列表可见范围**完全一致**。
- **列表可见范围与检索可见范围必须一致，不得出现"列表看不到但检索能命中"的破口**，反之亦然。
- 验收：对同一 admin、同一语料，做"列表可见文档集合"与"检索可命中文档集合"的一致性断言，两者在测试公司范围内相等，且均不含其它公司文档。

**P0-8 普通成员个人库私密性保持（R4 反例约束）**
- 一般成员的个人库保持私密：除本人外（含 admin）不可见、不可检索。
- admin 对个人文档的可见性**仅限其自建测试公司**这一窄口径，**不得放开成全局**。
- 验收：普通公司成员 A 的 private 文档，对 admin 不可见、对同公司其他成员不可见；admin 对非自建测试公司成员的 private 文档同样不可见。

### P1（应该）

**P1-1 文档页公司筛选器（R5）**
- 平台管理员可在文档页按公司筛选：`全部公司` / 指定公司。
- 筛选候选项 = admin 可见范围内的测试公司（与 P0-6 可见范围一致）。
- 验收：选择指定公司后，列表仅显示该公司文档；选择"全部公司"时显示可见范围内全部测试公司文档；筛选不改变可见范围上限。

**P1-2 改名后旧名不可再用于身份验证（R2 边界）**
- 改名后，旧公司名不再出现在身份验证候选；若旧名被提交，按"未注册公司"处理并提示。绑定以公司标识为准，不依赖名称匹配。
- 验收：改名"转入检索公司bjld8"→"测试公司1"后，用"转入检索公司bjld8"提交申请被拒绝；用"测试公司1"提交成功。

**P1-3 admin 自上传文档归属（R4 边界）**
- admin 上传文档时必须显式选择归属公司，且只能选择其自建测试公司；不产生"无公司归属"的文档。
- 验收：admin 上传文档未选择公司时不可提交；选择测试公司1后，该文档归属测试公司1并受同一可见范围约束。

### P2（可选）

**P2-1 公司操作的可见反馈**
- 创建/改名/审核成功后给出操作反馈与列表即时刷新。

**P2-2 公司名变更的轻量留痕**
- 记录"公司改名"事件（旧名→新名、时间、操作者），便于排查；不要求恢复旧名。

## 4. UI 交互说明

### ① 文档列表：三层标签新样式

标签结构 = `图标 + 层级词 + (· 公司/部门名)`。三种实际渲染：

```
个人文档        [🔒 个人]                         ← Lock 图标 + "个人"，不显示公司名
部门文档        [👥 部门 · 测试公司1 · 营销部门]     ← Users 图标 + "部门" + 公司名 · 部门名
公司文档        [🏢 公司 · 测试公司1]               ← Building2 图标 + "公司" + 公司名
```

> 说明：为满足"层级词仍要能看出来"，层级词（个人/部门/公司）保留在前，公司名/部门名作为其后的补充信息，用 `·` 分隔。若产品选择更紧凑的"公司名优先"排布（如 `测试公司1 · 营销部门` 且层级由图标承载），需同时保证图标可辨识——见待确认问题 Q1。

混排列表效果示例：

```
文档列表
┌───────────────────────────────────────────────────────────┐
│ 2024 营销方案.pdf     [👥 部门 · 测试公司1 · 营销部门]      │
│ 客户名单.xlsx         [👥 部门 · 测试公司2 · 销售部门]      │
│ 公司制度.docx         [🏢 公司 · 测试公司1]                 │
│ 我的笔记.md           [🔒 个人]                             │
└───────────────────────────────────────────────────────────┘
→ 现在能一眼看出：两份部门文档分属 测试公司1 / 测试公司2，不再混淆。
```

```

**身份验证表单：公司字段变化**
```
身份验证（提交申请）                      【改造前】
┌───────────────────────────────┐       ┌───────────────────────────────┐
│ 公司：  [ 测试公司1         ▾ ]│  ←→   │ 公司：  [ 自由输入___________ ]│
│ 部门：  [ 营销部门__________ ]│       │ 部门：  [ 自由输入___________ ]│

- 公司字段由自由输入改为**下拉选择**，候选来源为公司注册表。
- **用户填了不存在的公司**：下拉中不存在该选项 → 无法选中；若依旧走输入式交互，提交时校验失败并提示：
  `未找到该公司，请先联系管理员注册后再提交。`
- 提交后进入 pending；admin 在审核面板点击"同意"后，用户才成为该公司测试账号并进入该公司。

## 5. 待确认问题（按重要性排序，最多 5 条）

1. **"测试公司"的判定口径**：admin 可见范围定义为"自己创建的测试公司"，需要一个明确判定依据。
   - **默认取**：公司注册表中 `创建者 == admin` 的公司即视为其"测试公司"，admin 可见范围 = 这些公司的全部文档（含 private）。除非另有说明。
   - 影响：直接决定 P0-6/P0-7 的可见范围计算与检索过滤。

2. **admin 自建测试公司是否包含其"个人(private)"层级文档**：R4 明确 admin 可见测试公司的 private 文档，但 admin 自己上传选择"个人"层级时如何归属。
   - **默认取**：admin 不拥有独立个人库；admin 上传文档必须指定归属的测试公司（P1-3），其可见的 private 文档指"测试公司内成员的个人文档"。除非另有说明。
   - 影响：决定 admin 上传流程与 private 例外的作用域。

3. **部门名的权威来源**：文档标签里的"部门名"从哪里取。
   - **默认取**：取文档所属成员在其公司下的部门名（来源为身份验证申请的 `department_name`）。公司内同名部门视为同一部门。除非另有说明。
   - 影响：P0-1 部门标签能否稳定渲染。

4. **改名后"名称→公司标识"映射的替换规则**：现有 `company_id_from_name` 是确定性名称映射，改名会打破旧名映射。
   - **默认取**：身份验证绑定以公司注册表标识为准，名称仅用于展示与下拉选择；改名后新名可解析、旧名失效（P1-2）。除非另有说明。
   - 影响：身份验证与历史数据解析逻辑，需架构师确认实现方式。

5. **admin 未创建任何测试公司时的兜底**：列表/检索/筛选器行为。
   - **默认取**：文档列表与检索均为**空结果**，文档页显示引导"暂无测试公司，请先创建公司"；筛选器仅显示"全部公司 (0)"。除非另有说明。
   - 影响：避免"回退到全平台可见"的安全风险。

| P0-2 创建公司 | admin 创建公司 X → 公司列表出现 X，且身份验证公司下拉含 X | P0 |
| P0-3 重名 | 创建已存在公司名（含空格/大小写变体）→ 被拒绝并提示"公司已存在" | P0 |
| P0-4 改名 | 改 bjld8→测试公司1、1z5pp→测试公司2；断言成员数/文档数不变、标签显示新名、tenant_id 未变 | P0 |
| P0-5 身份验证绑定 | 提交已注册公司申请→admin 同意→用户归属该公司并可见其文档；提交未注册公司→被拒绝并提示；pending 期间不可见 | P0 |
