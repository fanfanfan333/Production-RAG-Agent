# 图检索完整回归与审核记录

## 验收口径

保留原120例（事实40、表格25、图片15、多跳20、无答案与冲突20），不改答案或替换难题。用相同代码、账号、模型、评分版本和逐题预热方式分别执行 `hybrid` 与 `hybrid_graph`，检查所有类别不退化、Recall@5至少95%、引用诊断至少98%、必要来源完整覆盖，以及图检索P95不高于普通检索的1.2倍。

原120例的普通检索多跳已经满分，不能在这个有天花板的子集上证明额外10个百分点增益。因此另保留独立的20道多跳和4道普通题，在另一私有知识库执行同配置成对测试。独立难题至少提升10个百分点，普通题不退化；不把两套资料拼成一个144例金标，不修改原对比器的完整集判定。

这24题参与过图检索缺陷定位与修复，属于固定开发诊断集，并非未见数据盲测。其收益用于验证已知问题是否修复，不能外推为真实企业业务的总体准确率。

`backend/scripts/check_graph_release.py` 汇总这两项自动质量检查。它要求两组配置、评分版本与账号范围一致，各自保留原始来源、完整预热和延迟门禁；知识库和金标必须不同。完整集的多跳增益未达10个百分点仍原样显示，独立集不足120例也仍原样显示。汇总工具不代签人工审核，不代替权限或资源验收。

复现入口（先完成真实上传与成对推理，报告和凭据留在本机）：

```powershell
cd backend
python -m scripts.check_graph_release FULL_HYBRID.json FULL_GRAPH.json HARD_HYBRID.json HARD_GRAPH.json
```

## AI辅助复核与真人签审

已对照原始MD、DOCX合并表格、3份扫描PDF表格、15张图片及公开论文原页核对120条参考答案。核对包括实体、年份、表格行列、数值单位、两跳中间实体，以及无答案和冲突的处理。参考答案来自显式原始资料，不使用模型回答作为真值。

本机复核表为 `.scratch/graph-release-20261019/gold-review-ai.csv`，详细记录为同目录 `gold-review-ai.json`，保留原金标及来源文件SHA256。复核者标为AI（Codex），真人结论、姓名和备注留空；不得写成“人工审核120例通过”。公开论文仅记录原页定位与简要转述，不将资料作为训练数据。

模型答案与参考答案的核对、自动字面规则、服务端引用诊断是不同层次。原文存在某个数字，不等于所有包含该数字的回答都正确；引用诊断通过也不代表独立的语义蕴含认证。无依据的拒答、遗漏一跳引用及无关内容必须在逐题答案复核中单列。

本轮已逐项阅读最终图策略120题及独立24题回答，并检查引用对应的原文；本机 `answer-review-ai.csv/json` 分组绑定两份最终报告SHA256、各自金标SHA256及来源文件校验记录。该复核仍标为AI（Codex），不是人工签审，不合并为144例金标。已明确保留：`fact-40`答案281分钟正确，但带无关8k摘录且主答案引用被警告移除；`table-15`、`table-25`数值正确但解释冗余，其中前者讨论不相关项目冲突。真人签审字段保持待审核，只有实际审核人的结论才能更新。

## 真实反馈与流式传输修复

真实回答的反馈接口曾因中文问号与已保存问题中的ASCII问号不同返回409。查询入库使用文本规范化，而反馈此前要求原始客户端文本完全相同。现在复用同一规范化函数，同时接受精确匹配的旧历史；问题、答案、所有者、租户仍必须对应真实回答记录，快照取服务端保存内容，不信任客户端造句。4项回归覆盖规范化、旧历史兼容、伪造问题及伪造答案。

通过实际Next.js生产服务器验证时，另发现首字几乎与整段结束同时到达。独立传输测试向同一代理发送两段相隔800毫秒的构造事件：不带no-transform时被gzip压缩，首事件817毫秒；增加 `Cache-Control: no-cache, no-transform` 后不再被压缩，首事件3.5毫秒，总流仍约813毫秒。该实验只证明流式传输，不是模型回答延迟成绩。

问答SSE响应头增加no-transform，并保留 `X-Accel-Buffering: no`。实际复验还发现安全网关会覆盖Cache-Control，因此网关在强制 `no-store` 时保留内部响应声明的no-transform；既避免代理压缩缓冲，也不放宽私有内容缓存策略，没有关闭其他页面和静态文件压缩。依据是[Next.js默认压缩说明](https://nextjs.org/docs/app/api-reference/config/next-config-js/compress)和[compression中间件的no-transform约定](https://github.com/expressjs/compression#api)，并对照本机实际安装源码验证；回归覆盖流式头部经过网关后仍保留指令、普通响应仍禁止缓存。

成对模型报告对应的检索、生成和资源权限判断与最终部署一致；成对测试后应用文件仅改动反馈API、问答SSE响应头和网关保留该传输指令三处。最终镜像中应用及脚本的文件SHA256均与工作区一致，记录在本机 `runtime-final.json`。接口与传输修改另做实际前端代理问答验证，不冒充又重跑了一轮完整成对模型评测。

最终部署通过实际 `next start` 的同源 `/api` 入口完成真实问答、原文分片查看、中文全角问题反馈提交200、伪造问题/答案409、跨账号反馈404及原文访问拒绝。响应确认为 `text/event-stream`、`Cache-Control: no-store, no-transform`，没有Content-Encoding；仅清理自身测试会话和1条测试反馈。登录页及代理健康检查返回200；认证使用真实账号的服务端签发令牌，未将浏览器密码登录或视觉交互当作本轮通过项目。

## 开启方式

按本次明确要求，本机 `backend/.env` 保存 `GRAPH_RETRIEVAL_ENABLED=true`，聊天页默认勾选关联检索，用户仍可切回普通检索。本机同时保留实际测试配置 `OLLAMA_NUM_GPU=-1`、`OLLAMA_KEEP_ALIVE_SECONDS=60`，直接通过现有低内存Compose配置读取，不依赖临时覆盖文件。通用服务配置的安全默认值仍是false，API未传策略时仍兼容普通 `hybrid`。图未索引或没有可信关系时保留明确回退提示；权限异常仍拒绝访问。

开启功能不等于人工签审或全场景发布认证。测试GPU配置的延迟不能外推到默认CPU配置，也不以串行预热结果宣称并发容量。

## 中断保护与非模型检查

实时图接口已通过所有者2项正向访问和10项跨账号/匿名探针。实际员工、另一租户部门主管对私有文档的图状态、证据和索引写入均返回404，匿名读取返回401；强制指定私有知识库的图问答明确拒答，返回来源0、路径0，没有暴露构造资料中的企业或园区答案。测试只清理自身创建的会话。原20例逐账号检索金标本日复测仍为Recall@5、MRR均1.0，另10个检索越权探针零命中；该20例不含生成质量评估。

第一轮全量成对运行在操作系统/Docker重启期间中断，日志停在第66题，没有最终报告，不计为完成。新版验收器逐题原子保存报告，记录预期题数、已创建会话和 `in_progress`；尚在进行或中断的报告不能通过对比器。重跑使用独立的 `paired-release-v4-20261019-*` 输出，不拼接已中断记录，也不覆盖旧证据。后台进程可避免普通对话中断导致整轮结果丢失，但不能跨越电脑重启继续推理。

锁定依赖的最终干净环境中，后端2047项通过、22项按环境跳过，权限专项1019项通过、1项跳过；测试容器限制2GB、1CPU。真实PostgreSQL副本与临时Qdrant集合的图证据检查1项通过，验证中断重试、对象ACL拒绝、旧原文失效和删除级联；该安全测试使用关系抽取替身，不能当作真实模型质量成绩。副本、临时集合及凭据文件已清理，备份仅留本机。

前端静态检查、5项测试和生产构建通过。线上完整资料集98份、独立难题资料集40份，文件SHA256及文档ID均与本机原始资料一致；同名文档分属各自知识库，不跨库混用。

真实推理保持启动前至少5GB、运行中低于1GB中止保护，并只串行执行。重启后的内存回收采用[微软官方说明](https://devblogs.microsoft.com/commandline/memory-reclaim-in-the-windows-subsystem-for-linux-2/)中的WSL缓存释放和内存整理，没有重启WSL或停止其他项目；只有先前获准的ForgeFlow OpenViking临时暂停，验收后按原容器ID恢复。

## 研究依据

- [Microsoft GraphRAG局部检索](https://microsoft.github.io/graphrag/query/local_search/)结合实体关系与原文文本单元，经过排序和过滤构建上下文。本项目复用原文、权限和统一精排，不另部署整套GraphRAG。
- [GraphRAG-Bench](https://arxiv.org/abs/2506.05690)分别评价检索、推理和生成，指出图检索并非所有任务都更好，因此完整格式回归与较难的多跳增益分别报告。
- [TopoGraphRAG-Bench，2026-10-07](https://arxiv.org/abs/2610.09360)强调图表、正文与版面之间的必要证据连接及反事实检查。本轮借鉴其证据完整性检查思路；当前资料不等同于该公开基准，不宣称已实现完整多模态版面图或通过其2024题测试。
